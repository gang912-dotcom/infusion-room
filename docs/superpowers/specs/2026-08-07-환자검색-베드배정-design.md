# 설계 — 환자 검색으로 베드 배정 (2026-08-07)

## 1. 배경

지금 환자를 베드에 넣는 경로는 하나다. **빈 베드를 누르고 → 등록 모달에서 차트번호를 직접
입력한다.** 차트번호를 blur하면 `/api/patients/lookup`이 이름과 특이사항을 채워 준다.

여기엔 두 가지 불편이 있다.

- **이름은 아는데 차트번호를 모르면 못 찾는다.** `lookup`은 차트번호 정확 일치만 지원한다.
- **베드를 먼저 정해야 한다.** 환자를 먼저 정하고 자리를 고르는 순서가 안 된다.

`환자 조회` 탭에 이름 검색이 이미 있지만 조회 전용이고, 데이터가 `GET /api/history`
(`WHERE s.ended_at IS NOT NULL`)라 **과거에 수액을 다 맞고 간 환자만** 나온다. 오늘 처음 온
환자도, 지금 이용 중인 환자도 그 목록엔 없다.

**이 설계는 배정 경로를 하나 더한다. 기존 경로는 그대로 둔다.**

## 2. 사용자 흐름

```
탭 바 밑  [환자 검색: 이름 또는 차트번호]  [검색]
   ↓ 결과 드롭다운
   김민수 (62349)
   김민수 (71204)                    ← 동명이인은 차트번호로 갈린다
   최지우 (58821)  이용 중 · 수액센터 3번
   ↓ 환자 선택
[배정 대기 중]  김민수(62349) 환자를 배정할 빈 베드를 선택해주세요.   [취소]
   ↓ 빈 베드 클릭
기존 등록 모달 — 환자명·차트번호·특이사항이 채워진 상태
근무자는 라인담당·진료실만 고르고 '배정'을 누른다
```

`이용 중` 환자를 누르면 배정 모드로 가지 않는다. **그 베드가 있는 탭으로 전환한다.**

## 3. 화면

### 3-1. 검색 바

- **자리**: 탭 바 바로 밑. **수액실 탭에서만 보인다**(`ROOM_TABS` = 전체·수액센터·2수액실·2층수액실).
  이용기록·환자조회·통계·데이터관리 탭에는 베드가 없어 배정이 성립하지 않는다.
- 한 줄(44px). 입력칸 + `검색` 버튼. Enter로도 검색한다.
- **한글 조합 중 Enter는 무시한다**(`e.nativeEvent.isComposing`). 조합이 끝나기 전에 보내면
  마지막 글자가 잘린다 — 채팅 입력에서 이미 겪은 함정이다.
- `inputMode`는 지정하지 않는다. 이름과 번호를 같은 칸에서 받으므로 문자 키보드가 기본이어야 한다.

### 3-2. 결과

- 칸 바로 밑에 **떠 있는 드롭다운**(absolute). 보드를 밀어내지 않는다.
- 줄 형식: `이름 (차트번호)`. 번호를 늘 함께 보여 동명이인을 가른다.
- 이용 중이면 뒤에 배지: `이용 중 · 수액센터 3번`.
- 결과 0건이면 `검색 결과가 없습니다. 신규 환자는 빈 베드를 눌러 등록하세요.` —
  왜 안 나오는지와 대안을 같이 준다.
- 바깥을 누르거나 ESC로 닫는다.

### 3-3. 배정 대기 모드

자리이동 모드와 **같은 구조·같은 자리·같은 스타일**을 쓴다. 근무자가 이미 아는 조작이다.

- 상태: `pendingPatient` (`{ chartNo, name, baselineNote }`)
- 안내 바: `.move-banner`와 같은 자리에 `배정 대기 중` 라벨 + 환자 이름 + `취소`
- 빈 베드는 `bed-card--movable`로 강조, 나머지는 `bed-card--dimmed`
- ESC로 해제 — 기존 ESC 핸들러 체인에 `pendingPatient`를 추가한다
- **모드 중에는 보드 폴링을 멈춘다.** `isModalBusyRef`에 `pendingPatient`를 더한다 —
  `movingBed`가 이미 거기 들어 있는 것과 같은 이유다. 베드를 고르는 동안 보드가 다시 그려지면
  누르려던 카드가 손가락 밑에서 움직인다.

### 3-4. 베드 클릭

`handleBedClick` 맨 앞에 분기를 하나 더한다. 순서는 `movingBed` → `pendingPatient` → 기존.

- 빈 베드가 아니면 안내만 하고 모드를 유지한다(자리이동과 같은 문구 패턴)
- 빈 베드면 기존과 똑같이 `acquireBedLock` → 실패하면 모드 유지, 다른 베드 재선택
- 잠금에 성공하면 `openModal(bed)`을 부르되 **`patientName`·`chartNumber`·`specialNote`·
  `lookupInfo`를 미리 채운다**. `lookupInfo`를 같이 채워야 라인담당을 고른 순간
  특이사항 안내 모달이 기존과 똑같이 뜬다.
- **채운 값은 읽기 전용으로 두지 않는다.** 잘못 고른 경우 그 자리에서 고칠 수 있어야 한다.
- 모달에서 취소하면 배정 대기 모드도 **해제한다**(근무자의 명시적 취소다).

## 4. 서버 — `GET /api/patients/search?q=`

`server/routes/patients.js`의 `lookup` 옆에 둔다.

- 대상은 **`patients` 테이블**이다. 배정된 적 있는 모든 환자가 들어 있다.
- 검색 규칙은 `환자 조회` 탭과 **같게** 한다:
  **이름은 부분 일치, 차트번호는 앞자리 일치.**
  번호를 부분 일치로 두면 `2444`가 `2244414` 가운데에 걸려 엉뚱한 환자가 섞인다.
- 정렬은 차트번호 오름차순(`numeric` 비교). 상한 30건. 빈 `q`는 빈 배열.
- 응답에 `baseline_note`와 현재 베드를 같이 실어 왕복을 늘리지 않는다.

```json
[
  { "chart_no": "58821", "name": "최지우", "baseline_note": "당뇨",
    "active": { "room": "room3", "bed_number": "3" } },
  { "chart_no": "62349", "name": "김민수", "baseline_note": null, "active": null }
]
```

`active`는 `sessions`에 `ended_at IS NULL AND cancelled = 0`인 행이 있을 때 채운다.
**§5-①의 유니크 인덱스 조건과 한 글자도 다르면 안 된다.** 여기에 `deleted = 0`을 더하면
휴지통에 넣었지만 종료되지 않은 세션이 인덱스에는 잡히고 화면에는 안 보여서,
근무자가 "이용 중이 아닌데 배정이 거부되는" 상황을 만난다. 기존 베드 인덱스도 같은 조건이다.

방 라벨(`수액센터`)은 서버에 두지 않는다 — 클라의 `ROOM_LABELS`가 정본이다.

**접근 로그는 남기지 않는다.** 기존 방침이 "상세를 열 때만 남기고, 검색어를 치는 중이거나
목록만 보는 단계는 대상이 아니다"이다. `POST /patients/:chartNo/detail-view`가 그 자리를 맡는다.

## 5. 같은 환자가 두 베드에 들어가는 것 막기

지금 유니크 인덱스는 **베드 기준**이라(`idx_sessions_one_active ON sessions(bed_id)`)
같은 환자가 두 베드를 차지하는 걸 막는 장치가 없다. 이름 검색이 생기면 이용 중인 환자가
결과에 그대로 떠서 훨씬 쉽게 발생한다.

세 겹으로 막는다. **각각이 다른 것을 막으므로 하나로 줄일 수 없다.**

### ① DB — 부분 유니크 인덱스 (경합까지 막는 유일한 층)

```sql
CREATE UNIQUE INDEX IF NOT EXISTS idx_sessions_one_active_patient
  ON sessions(patient_id) WHERE ended_at IS NULL AND cancelled = 0;
```

베드에 이미 같은 패턴이 있다. 두 근무자가 **동시에** 같은 환자를 다른 베드에 넣는 경우는
이것만이 막는다. 종료·취소된 세션은 조건에서 빠지므로 같은 환자가 오늘 다시 오는 건 정상이다.

운영 DB에 이미 위반이 있으면 인덱스 생성이 실패한다. **그때는 어느 환자인지 로그에 찍고
넘어간다.** `IF NOT EXISTS`라 settings 플래그 없이 매 기동 다시 시도하므로, 그 환자를 정리하면
다음 기동에 저절로 만들어진다. 마이그레이션이 데이터를 자동으로 고치지는 않는다 —
진행 중인 세션을 코드가 임의로 종료시키면 안 된다.

(맥 dev DB 실측: 위반 0건. 운영 DB는 확인하지 못했다.)

### ② 서버 — assign 라우트 가드 (읽을 수 있는 메시지)

`INSERT INTO sessions`는 `POST /api/sessions/assign` 한 곳뿐이다([sessions.js:108]).
**두 배정 경로가 모두 여기를 지난다.** 인덱스만 있으면 근무자에게 `SQLITE_CONSTRAINT`가
보이므로, 배정 전에 확인해서 409로 돌려준다.

> `최지우 환자는 이미 수액센터 3번에 배정돼 있습니다.`

### ③ 화면 — 검색 결과 배지 (애초에 안 누르게)

`이용 중 · 수액센터 3번`을 표시하고, 누르면 배정 대신 그 베드가 있는 탭으로 전환한다.

## 6. 재사용하는 기존 코드

| 필요한 것 | 이미 있는 것 |
|---|---|
| 검색 규칙 | `PatientView`의 이름 부분일치 + 번호 앞자리 일치 |
| 안내 바 | `.move-banner` (자리이동 중) |
| 빈 베드 강조 / 딤 | `bed-card--movable`, `bed-card--dimmed` |
| ESC 해제 | 기존 ESC 핸들러 체인 |
| 베드 클릭 분기 | `handleBedClick` |
| 배정 모달·베드 잠금·특이사항 안내 | `openModal` 그대로, 상태 4개만 프리필 |
| 방 라벨 | `ROOM_LABELS` (api.js 정본) |

새로 만드는 것은 **검색 바 컴포넌트 하나와 서버 엔드포인트 하나**다.

## 7. 실패 처리

| 상황 | 동작 |
|---|---|
| 베드 잠금 실패(남이 등록 중, 409) | 안내 후 **모드 유지** — 다른 베드 재선택 |
| 배정 중 다른 사람이 같은 베드 선점 | 안내 후 **모드 유지** |
| 이미 다른 베드에 배정된 환자(409) | 안내 후 **모드 해제** — 배정 자체가 성립하지 않는다. 배지가 걸러 주므로 검색한 뒤 배정하기까지 사이에 남이 먼저 배정한 경우에만 여기까지 온다 |
| 사용 중인 베드 클릭 | 안내만, 모드 유지 |
| 모달에서 취소 | 모드 해제 |
| 검색 요청 실패 | 칸 밑에 오류 문구. 참조 데이터와 달리 재시도하지 않는다(사용자가 다시 누르면 된다) |

## 8. 검증

로그인(비밀번호 입력)이 막혀 있어 화면 실조작은 못 한다. 기존 관례를 따른다.

1. **검색 규칙을 순수 함수로 뽑아 node로 검증.** 이름 부분일치·번호 앞자리 일치·정렬·상한.
   `2444`가 `2244414`에 안 걸리는지 반드시 포함한다.
2. **서버 엔드포인트는 DB 복사본에 붙여 확인.** `active` 판정(진행 중·종료·취소·삭제 4가지),
   빈 `q`, 상한.
3. **유니크 인덱스는 DB 복사본에 먼저 적용.** 위반이 있는 DB를 일부러 만들어
   "실패해도 기동은 계속되고 로그가 남는지"까지 확인한다.
4. **검색 바·드롭다운·안내 바는 실제 CSS로 하니스 렌더**해 폭·줄바꿈·대비를 실측한다.
   흰 글자를 얹는 배경이 생기면 `--solid-*`를 쓴다.
5. eslint 베이스라인 1건을 넘기지 않는다.

## 9. 범위 밖 (안 한다)

- **신규 환자 사전 등록.** 한 번도 온 적 없는 환자는 여전히 기존 경로로 등록한다.
  검색 결과 0건 문구가 그 길을 안내한다.
- **환자 정보 편집 화면.** 이름·차트번호 수정은 이 설계에 없다.
- **검색 결과 페이지네이션.** 상한 30건으로 충분하다.
- **기존 `환자 조회` 탭 개편.** 조회 전용으로 그대로 둔다.

## 10. 남는 것

- **운영 DB에 활성 세션 중복이 있는지 확인하지 못했다.** 배포 후 서버 로그에
  인덱스 생성 실패 메시지가 있는지 본다.
- 검색 바가 한 줄(44px)을 차지해 수액실 탭의 보드가 그만큼 줄어든다.
  아이패드 세로에서 카드가 한 줄 덜 보이면 돋보기 버튼으로 접는 선택지가 있다.
