수액실 서버를 **다른 윈도우 PC로 옮길 때** 보는 문서.

- 관련 문서: `운영_서비스관리.md`(서비스 조작), `운영_백업복원.md`(백업/복원), `배포보고서_7d7e.md`(최초 구축 기록)

## 0. 먼저 확인할 것

### 코드는 파일 복사가 아니라 git으로 옮긴다
USB로 폴더를 복사하지 말 것. **작업하던 기계에서 push → 새 PC에서 clone** 이 전부다.

> ⚠️ **clone 전에 push가 끝나 있어야 한다.** 안 그러면 새 PC가 옛 코드를 받는다.
> 맥에서 작업 중이었다면 `git push origin server-migration` 먼저.

### 데이터를 가져갈지 말지 결정
- **테스트 데이터뿐이라 버려도 됨** → 4단계에서 새로 시드. 이 문서의 기본 경로.
- **환자 실데이터를 유지해야 함** → 4단계를 건너뛰고 아래 "부록 A: 데이터까지 옮기기" 참고.

### 새 PC에 필요한 것
- 윈도우, 관리자 권한
- 인터넷(clone·npm)
- **D: 드라이브** — 없으면 6단계의 백업 경로 수정 필요
- Git·Node 설치 (1~2단계)
- **`nssm.exe`** — 구 PC `C:\iv-app\tools\nssm.exe` 를 USB 등으로 미리 챙겨올 것.
  gitignore 대상이라 clone에 안 들어온다. 이걸 빼먹으면 7단계에서 멈춘다.

> 저장소가 **공개**라서 clone·pull에 GitHub 로그인이 필요 없다. 서버 PC는 pull만 하므로
> 자격증명을 저장할 일도 없다(push는 작업 기계에서만).

## 1. Node.js 설치

기존 서버는 **v24.18.0 (x64)** 를 쓴다. 같은 계열(v24.x LTS)을 **기본 경로**에 설치할 것.

```
C:\Program Files\nodejs\node.exe
```

`admin-setup.bat`에 이 경로가 그대로 박혀 있다. 다른 곳에 설치하면 그 파일의 `set "NODE=..."` 줄을 고쳐야 한다.

확인:
```cmd
node -v
```

## 2. 코드 clone

**경로를 `C:\iv-app`으로 맞출 것.** 배치파일들이 이 경로를 기준으로 쓰여 있어서, 같게 두면 아무것도 안 고쳐도 된다.

```cmd
git clone https://github.com/gang912-dotcom/infusion-room.git C:\iv-app
```

> 저장소 루트 안에 `infusion-room\` 서브폴더가 실제 앱 루트다(package.json 위치).
> 즉 앱 디렉터리는 **`C:\iv-app\infusion-room`**.

```cmd
cd /d C:\iv-app\infusion-room
git checkout server-migration
```

> ⚠️ **브랜치 `server-migration`을 반드시 체크아웃할 것.**
> `main`은 서버 전환 이전의 localStorage 구버전이다. 그대로 두면 완전히 다른 앱이 뜬다.

## 3. 의존성 설치 + 빌드

```cmd
npm ci
npm run build
```

- `better-sqlite3`가 네이티브 모듈이라 이 PC에 맞게 준비된다. npm11이 빌드 스크립트를 차단한다는 경고가 떠도 v12는 prebuilt 바이너리를 포함하므로 문제없다.
- `npm run build`가 `dist\`를 만든다. **`dist\`가 있어야 서버가 앱까지 서빙한다**(없으면 API 전용 모드로 뜬다).

## 4. DB 시드 (새로 시작하는 경우)

cmd는 `VAR=값 명령` 문법이 **안 먹는다.** 환경변수를 따로 세팅할 것.

```cmd
set ADMIN_INITIAL_PASSWORD=원하는비밀번호
npm run db:seed
```

정상 출력:
```
시드 완료: { beds: 30, settings: 8, symptom_codes: 9, action_codes: 5,
             round_states: 4, note_categories: 3, note_sources: 3,
             accounts: 1, staff: 8 }
```

- 계정은 `admin` 하나. 비밀번호는 위에서 넣은 값.
- 직원 8명(이현숙·박민순·박소연·최유진·신현지·최지우·신예슬·김지윤), 베드 30개가 함께 들어간다.
- `.env`는 쓰지 않는다. 비밀번호는 이 한 번의 환경변수로만 전달되고 디스크에 평문으로 남지 않는다.

> 이미 DB가 있는 상태에서 다시 시드해도 admin 비밀번호는 **바뀌지 않는다**(`INSERT OR IGNORE`).
> 비밀번호를 바꾸려면 앱에서(데이터관리 → 계정 관리) 변경할 것.

## 5. nssm 배치

`tools\`는 gitignore 대상이라 clone에 포함되지 않는다. 직접 넣어야 한다.

```
C:\iv-app\tools\nssm.exe
```

**기존 서버 PC의 `C:\iv-app\tools\nssm.exe`를 복사해 오는 게 가장 확실하다.** (새로 받으려면 nssm 공식 배포본 win64 버전)

## 6. 백업 경로 확인 — D: 드라이브

새 PC에 **D: 드라이브가 없으면 백업이 실패한다.** 경로가 두 곳에 박혀 있다.

| 파일 | 박혀 있는 값 |
|---|---|
| `backup.bat` | `D:\iv-backup\backup.log` (로그 append 경로) |
| `server/backup.js` | 기본 백업 폴더 `D:\iv-backup` (단, `BACKUP_DIR` 환경변수로 덮을 수 있음) |

**D: 가 있으면** 아무것도 안 해도 된다 → 7단계로.

**D: 가 없으면** `backup.bat`의 경로를 원하는 위치로 바꾼다(예: `C:\iv-backup`). 파일 안 `D:\iv-backup` 을 전부 치환하고, `server\backup.js`에는 `BACKUP_DIR`을 넘긴다:

```bat
cd /d C:\iv-app\infusion-room
set BACKUP_DIR=C:\iv-backup
echo [%date% %time%] backup start >> C:\iv-backup\backup.log
node server\backup.js >> C:\iv-backup\backup.log 2>&1
```

> 이 하드코딩을 한 곳에서만 정하도록 정리하는 건 아직 안 했다. 이전을 계기로 손보면 좋다.

## 7. 관리자 설정 (방화벽 + 서비스 + 백업 스케줄)

`C:\iv-app\infusion-room\admin-setup.bat` → **우클릭 → 관리자 권한으로 실행**

한 번에 세 가지를 잡는다.

1. 방화벽 TCP 4000 인바운드 허용(private·domain 프로필)
2. nssm으로 `iv-app` 윈도우 서비스 등록 — 부팅 시 자동 시작, 죽으면 3초 후 자동 재시작, 로그 10MB 회전
3. 작업 스케줄러에 매일 03:00 DB 백업 등록

정상 종료 시 `Service is RUNNING.` 이 뜬다. 실패하면 그 자리에서 원인이 출력되고 아무것도 안 바꾼 채 멈춘다.

확인:
```cmd
sc query iv-app
```

## 8. IP 고정 — 가장 놓치기 쉬운 단계

| | 주소 |
|---|---|
| 구 서버 (단말들이 지금 보고 있는 곳) | `http://192.168.0.248:4000` |
| **신 서버** | **`http://192.168.0.86:4000`** |

공유기 관리 페이지 → DHCP 예약(고정 IP 할당) → **새 PC의 MAC 주소에 `192.168.0.86` 지정.**
새 PC의 MAC·현재 IP는 `ipconfig /all` 로 확인한다.

**주소가 바뀌므로 아래 두 가지를 반드시 같이 처리해야 한다.**

### ① 단말 주소를 전부 다시 등록
아이패드 홈 화면 바로가기, PC 즐겨찾기가 `192.168.0.248`을 가리키고 있다.
**`192.168.0.86`으로 하나씩 다시 등록**해야 한다. 대수를 미리 세어두면 좋다.

- 아이패드: 사파리로 새 주소 접속 → 공유 → **홈 화면에 추가** (기존 아이콘은 삭제)
- PC: 즐겨찾기/시작페이지 수정

### ② 로그인이 전부 풀린다 — 미리 공지할 것
로그인 쿠키는 접속 주소(오리진) 단위로 저장된다. 주소가 바뀌면 기존 30일 쿠키가 따라오지 않아
**모든 단말이 다시 로그인**해야 한다. 고장이 아니라 정상 동작이지만, 이전 직후 근무자가
"로그인 화면이 떴다"고 놀랄 수 있으니 미리 알려둘 것.

### 앱 자체는 IP가 바뀌어도 고칠 게 없다
프론트가 `fetch('/api...')` 상대경로로 호출하므로(`src/api.js`) 브라우저가 접속한 주소를 그대로 따라간다.
소스에 IP가 박힌 곳은 없고, 서버는 특정 IP가 아니라 모든 인터페이스에서 4000을 받는다.
방화벽 규칙도 포트 기준이라 IP와 무관하다. **코드·설정 수정은 필요 없다.**

> 참고 — 구 PC와 신 PC가 동시에 켜져 있어도 IP가 다르므로 충돌은 없다.
> 다만 **두 대가 같이 살아 있으면 근무자가 어느 쪽에 기록했는지 알 수 없게 된다.**
> 전환이 끝나면 13단계로 구 PC를 확실히 정리할 것.

## 9. 접속 확인

새 PC에서:
```cmd
C:\iv-app\infusion-room\check-server.bat
```
(관리자 권한 불필요. 서비스 상태를 보여주고 브라우저를 띄운다.)

다른 PC·아이패드에서:
```
http://192.168.0.86:4000
```
로그인 화면이 뜨면 성공. `admin` / 4단계에서 넣은 비밀번호로 로그인.
베드 30개가 보이는지, 배정 → 투여 시작이 되는지까지 확인하면 확실하다.

## 10. 재부팅 테스트

새 PC를 재부팅한 뒤 **아무것도 실행하지 않은 상태에서** 위 주소가 뜨는지 확인한다. 이게 통과해야 이전이 끝난 것이다.

## 11. 구 PC 정리

새 PC가 정상 동작하는 걸 확인한 **다음에** 한다.

```cmd
"C:\iv-app\tools\nssm.exe" stop iv-app
"C:\iv-app\tools\nssm.exe" remove iv-app confirm
schtasks /Delete /TN "IVApp-DB-Backup" /F
netsh advfirewall firewall delete rule name="IVApp-Port4000"
```

두 대가 같이 켜져 있으면 IP가 충돌하고, 근무자가 어느 쪽에 기록했는지 알 수 없게 된다. 구 PC는 서비스를 확실히 끄고 네트워크에서 뺄 것.

## 코드 업데이트 (이전 후 평상시)

작업 기계에서 push한 뒤, 서버 PC에서 **관리자 권한으로**:

```
C:\iv-app\infusion-room\deploy.bat
```

`git pull → npm ci → npm run build → nssm restart iv-app` 을 순서대로 한다. 중간에 실패하면
그 자리에서 멈추고, **빌드가 실패했으면 서비스를 재시작하지 않는다**(돌아가던 버전이 유지됨).

> 과거에 `deploy.bat`이 `nssm`을 전체 경로 없이 호출해서 `C:\iv-app\tools`가 PATH에 없으면
> 마지막 재시작 단계에서 실패하는 문제가 있었다. **2026-07-29에 전체 경로로 수정됨** — 이제 PATH와 무관.

## 부록 A: 데이터까지 옮기기

환자 실데이터를 유지해야 하는 경우. **4단계(시드)를 건너뛰고** 아래를 한다.

DB는 gitignore 대상(`server/data/*.db*`)이라 clone에 포함되지 않는다.

### 방법 1 — 스냅샷 (권장, 서비스 안 끔)

구 PC에서:
```cmd
cd /d C:\iv-app\infusion-room
node server\backup.js
```
`D:\iv-backup\infusion-YYYY-MM-DD_HHmm.db` 가 생긴다. WAL 모드에서도 일관된 상태를 `VACUUM INTO`로 떠낸 단일 파일이다.

이 파일을 새 PC의 다음 위치에 **`infusion.db`** 라는 이름으로 놓는다.
```
C:\iv-app\infusion-room\server\data\infusion.db
```

### 방법 2 — 원본 복사 (서비스 정지 필수)

```cmd
"C:\iv-app\tools\nssm.exe" stop iv-app
```
정지한 뒤 `server\data\` 의 **세 파일을 함께** 복사한다.
```
infusion.db
infusion.db-wal
infusion.db-shm
```

> ⚠️ 서비스가 돌아가는 중에 `infusion.db` 하나만 복사하면 **WAL에 있던 최근 기록이 빠진다.**
> 반드시 정지 후 세 파일을 함께 옮기거나, 방법 1을 쓸 것.

### 옮긴 뒤
- 시드하지 말 것. 시드하면 빈 DB가 만들어진다.
- 계정·직원·설정·환자 기록·접근 로그가 전부 DB 안에 있으므로 그대로 따라온다. **admin 비밀번호도 그대로다.**
- 서버 시작 후 앱에서 이용기록·환자 조회가 정상인지 확인.
